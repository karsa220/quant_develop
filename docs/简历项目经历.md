## 项目一（主推，深度项）：期货行情低延迟数据链路引擎

**期货行情低延迟数据链路引擎（C++17 / 跨平台）** ｜ 个人项目 ｜ 2026

**技术栈**：C++17、无锁 SPSC 环形队列、共享内存 mmap（Linux `/dev/shm` + Windows 命名映射）、`timerfd` 定时调度、CTP 风格二进制协议、Cache-line 隔离与 false-sharing 优化、perf 延迟百分位统计

**项目概述**：从零搭建一条覆盖「期货行情采集 → 定时调度 → 行情网关 → 共享内存零拷贝 → 低延迟消费/策略信号」的完整数据链路，对标量化私募行情系统核心模块的工程实现，并在本机完成跨进程 IPC 与性能基准验证。

**核心工作**
- **行情采集与网关**：实现期货合成行情源（6 个主力合约，泊松过程到 ticks、随机游走生成中间价），自研 CTP 风格二进制线协议（magic+type+len+payload+checksum，`#pragma pack(1)`），单线程编码吞吐 **31.8M ticks/s（≈30ns/tick）**。
- **低延迟消息处理**：设计无锁 SPSC 环形缓冲，生产者/消费者指针 64 字节 cache-line 隔离、`acquire/release` 内存序、发布/消费 O(1)；经基准对比，较 `std::mutex + deque` 朴素队列吞吐提升 **约 8.2×**（8.10M vs 0.99M msg/s），p99 延迟从百微秒级降到微秒级。
- **共享内存 / mmap**：基于 `shm_open`+`mmap`（Linux）与命名 `FileMapping`（Windows）跨进程映射同一段环形缓冲，网关与策略进程**零拷贝**传递行情；实测两个独立进程间发布 13,236,632 ticks、消费 13,236,632 ticks，**跨进程零丢失**。
- **Linux 定时任务**：用 `timerfd_create` 实现 `CLOCK_MONOTONIC` 周期心跳与 `CLOCK_REALTIME` 绝对定时（开盘 09:30 / 收盘 15:00 会话信号），并配套 systemd 服务（`Restart=always` 保活）与 cron 收盘快照脚本，覆盖生产环境调度与运维链路。
- **完整链路与基准**：进程内端到端跑通「采集→网关→共享内存→消费→反转信号」，4s 内处理 **21.5M ticks、零丢弃、5.37M ticks/s**，tick→信号延迟 **p50≈200ns / p99≈1.35ms**；配套 `LatencyRecorder` 输出 p50/p90/p99/p99.9 百分位。
- **质量保障**：单测覆盖环形队列顺序/满溢/并发、协议编解码双向、行情合法性、定时器等，**全部断言通过（985k+ checks）**；提供 Makefile / CMake（含 ctest）与跨平台（Win32 + Linux）构建。

**个人职责**：架构设计、全模块编码、跨平台 IPC 与内存对齐调试、性能基准与延迟分析、Linux 调度/运维脚本、单测与文档。

## 英文版（部分外企/英文简历用）

**Low-Latency Futures Market-Data Pipeline (C++17, cross-platform)** — Personal project
Built an end-to-end low-latency pipeline: synthetic futures feed → `timerfd` scheduling → market-data gateway → shared-memory (mmap) zero-copy IPC → consumer/strategy signals. Highlights:
- Lock-free SPSC ring buffer with cache-line isolation & acquire/release ordering; **~8.2× throughput vs mutex+deque** (8.10M vs 0.99M msg/s).
- Cross-process shared memory validated **lossless** (13.236M ticks produced = consumed) on both Linux `/dev/shm` and Windows named mapping.
- In-process E2E: 21.5M ticks in 4s @ 5.37M ticks/s, **tick→signal p50≈200ns, p99≈1.35ms**.
- CTP-style binary wire protocol @ 31.8M ticks/s; systemd + cron for session open/close scheduling; 985k+ unit-test checks passing.
