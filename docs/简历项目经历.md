## 项目一（主推，深度项）：期货行情低延迟数据链路引擎

**期货行情低延迟数据链路引擎（C++17 / 跨平台）** ｜ 个人项目 ｜ 2026

**技术栈**：C++17、无锁 SPSC 环形队列、共享内存 mmap（Linux `/dev/shm` + Windows 命名映射）、`timerfd` 定时调度、CTP 风格二进制协议、Cache-line 隔离与 false-sharing 优化、perf 延迟百分位统计

**项目概述**：从零搭建一条覆盖「期货行情采集 → 定时调度 → 行情网关 → 共享内存零拷贝 → 低延迟消费/策略信号」的完整数据链路，对标量化私募行情系统核心模块的工程实现，并在本机完成跨进程 IPC 与性能基准验证。

**核心工作**
- **行情采集与网关**：实现期货合成行情源（6 个主力合约，泊松过程到 ticks、随机游走生成中间价），自研 CTP 风格二进制线协议（magic+type+len+payload+checksum，`#pragma pack(1)`），单线程编码吞吐 **31.8M ticks/s（≈30ns/tick）**。
- **低延迟消息处理**：设计无锁 SPSC 环形缓冲，生产者/消费者指针 64 字节 cache-line 隔离、`acquire/release` 内存序、发布/消费 O(1)；经基准对比，较 `std::mutex + deque` 朴素队列吞吐**数倍提升（本机多次实测 1.3×~8.2×，取决于线程调度）**，且 lock-free 的 **p50 稳定 ~200ns**、互斥队列 p50 数十 µs——这是更稳的硬指标。
- **共享内存 / mmap**：基于 `shm_open`+`mmap`（Linux）与命名 `FileMapping`（Windows）跨进程映射同一段环形缓冲，网关与策略进程**零拷贝**传递行情；实测两个独立进程间发布 13,236,632 ticks、消费 13,236,632 ticks，**跨进程零丢失**。
- **Linux 定时任务**：用 `timerfd_create` 实现 `CLOCK_MONOTONIC` 周期心跳与 `CLOCK_REALTIME` 绝对定时（开盘 09:30 / 收盘 15:00 会话信号），并配套 systemd 服务（`Restart=always` 保活）与 cron 收盘快照脚本，覆盖生产环境调度与运维链路。
- **完整链路与基准**：进程内端到端跑通「采集→网关→共享内存→消费→反转信号」，4s 内处理 **21.5M ticks、零丢弃、5.37M ticks/s**，tick→信号延迟 **p50≈200ns / p99≈1.35ms**；配套 `LatencyRecorder` 输出 p50/p90/p99/p99.9 百分位。
- **风控模块**：实现 `RiskControl`——行情进入策略前做价格区间/行情时效（拒重放）/净持仓限额校验，下单令牌桶限流，全局熔断 kill-switch；坏点/乌龙指在策略执行前拦截，监控越界可联动拉闸进入安全态。
- **监控告警与交易日志**：实现 `Monitor`——分级日志、指标计数器、延迟直方图、**看门狗线程**（丢弃率/p99/卡顿越界即告警），`telemetryJson()` 供 `/metrics` 暴露，支持线上快速定位与熔断后恢复。
- **网络编程与多协议接口**：`net/` 模块实现行情 UDP/TCP 网络采集、链路层抓包（Linux `AF_PACKET`/Windows `SIO_RCVALL`）、以及 TCP 二进制流 / HTTP REST-JSON / UDP 组播三种对外数据接口；I/O 多路复用抽象在 **Linux 用 epoll、Windows 用 WSAPoll**（reactor 事件循环），体现零拷贝与高并发。
- **性能优化手段**：无锁 SPSC（去锁）、mmap 共享内存（去拷贝）、cache-line 隔离（防伪共享）、热路径零分配 + 无锁对象池 `ObjectPool`（Treiber 栈，去 new/delete 抖动）、epoll（网络 IO 高并发）。
- **C++20 协程异步服务（JD 加分项）**：实现 `Task<T>`/`Task<void>`/`Generator<T>` 协程原语与单线程 `EventLoop`，复用现有 epoll/WSAPoll 多路复用器做就绪通知，「一连接一协程」`co_await` 串起收/发/等 ack；`AsyncMdServer` 收 CTP 风格 tick→`RiskControl` 风控→回 ack，**零线程零锁**。单线程事件循环下 8 客户端 × 5000 ticks 零丢失、零拒绝、ack 全回，RTT p50≈110µs / p99≈139µs；配套 `test_coro` 14 checks 全过。
- **质量保障**：单测（环形队列顺序/满溢/并发、协议双向、行情合法性、定时器）、网络层单测、以及**端到端集成测试**（20w ticks 跨进程零丢失、背压、看门狗告警、熔断、持仓限额、对象池并发）——**全部断言通过（单元 985k+ + 网络 23 + 集成 95 checks）**；提供 Makefile / CMake（含 ctest）与跨平台（Win32 + Linux）构建。

**个人职责**：架构设计、全模块编码、跨平台 IPC 与内存对齐调试、性能基准与延迟分析、Linux 调度/运维脚本、单测与文档。

## 英文版（部分外企/英文简历用）

**Low-Latency Futures Market-Data Pipeline (C++17, cross-platform)** — Personal project
Built an end-to-end low-latency pipeline: synthetic futures feed → `timerfd` scheduling → market-data gateway → shared-memory (mmap) zero-copy IPC → consumer/strategy signals. Highlights:
- Lock-free SPSC ring buffer with cache-line isolation & acquire/release ordering; **~8.2× throughput vs mutex+deque** (8.10M vs 0.99M msg/s).
- Cross-process shared memory validated **lossless** (13.236M ticks produced = consumed) on both Linux `/dev/shm` and Windows named mapping.
- In-process E2E: 21.5M ticks in 4s @ 5.37M ticks/s, **tick→signal p50≈200ns, p99≈1.35ms**.
- CTP-style binary wire protocol @ 31.8M ticks/s; systemd + cron for session open/close scheduling; 985k+ unit-test + 23 network + 95 integration checks passing.
- Added `RiskControl` (price/position/rate-limit + kill-switch), `Monitor` (logging, metrics, watchdog alerts, telemetry), lock-free `ObjectPool`, and epoll/WSAPoll `IoMultiplexer` for the data interfaces.
- Implemented a C++20 coroutine layer (`Task<T>`/`Generator<T>` + single-threaded `EventLoop` over epoll/WSAPoll); `AsyncMdServer` handles one coroutine per connection, doing CTP-tick → `RiskControl` → ack with **zero threads and zero locks** — 8 clients × 5000 ticks lossless, RTT p50≈110µs, 14 coroutine checks passing.
